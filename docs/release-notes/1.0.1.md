HSF 1.0.1 fixes the sound of voices with a filter, and the lengths of sequences whose counted loops outlast the ten-minute limit. `hsfrip` also finds a Bezel Engine game's `boot.lua` and sound effect list in more folder layouts.

HSF rips Nintendo Switch sequenced music into a PSF-family format. It plays the music with a model of the SDK's sound library and of the console's audio renderer, with the reverb a game puts on the music. The release includes a ripper (`hsfrip`), a renderer (`hsfplay`) and a foobar2000 component. `docs/hsf.md` describes the format.

The programs run on Windows 10 or later and require no runtime DLLs. To install the component, open the file with foobar2000, or add it under Preferences › Components. For macOS, see the README for instructions on building from source.

## Fixed in 1.0.1

- **Voices with a filter.** The audio renderer filters each voice in place. HSF's renderer took two of a block's filtered samples as the next block's input. Every voice with a biquad filter or the sound library's low-pass then went wrong from its fifth sample. In some sound effects the error was as loud as the sound. In music it was much quieter. HSF's renderer now gives the same samples as Nintendo's renderer, the build for the CPU in games' `sdk` modules. The lengths of some rips change slightly.
- **Counted loops that outlast the limit.** A sequence can repeat a loop a set number of times, for longer than the ten-minute limit. `hsfrip` gave such a sequence the limit. The ripper now measures it as a sequence that loops for ever. Such a sequence now gets two loops and a fade.
- **`boot.lua` below the folder given.** `hsfrip` takes a Bezel Engine game's voice count from its `boot.lua`. It looked for the file only at the top of the folder given. A folder that holds the RomFS in a subfolder then ripped with the default voice count. `hsfrip` now takes the `boot.lua` nearest the top.
- **Unpacked Bezel Engine archives.** `hsfrip` takes the reverb's settings from the game's sound effect list. The list sits in one of the game's Bezel Engine archives. `hsfrip` now also reads the list in an archive that was unpacked into a folder. Such a folder used to rip with no reverb.
- **The voice count's label.** `hsfrip` labels the voice count "(boot.lua)" only when `boot.lua` gave it. The label used to show with `--voices` too. It also showed for a count from `boot.lua` outside 1 to 96. `hsfrip` doesn't use such a count.
- **Broken links.** A broken link in a game's folder no longer stops `hsfrip` partway through the folder.
- **Hand-made rips.** A rip whose reverb density is well below 0 no longer makes the player write outside the reverb's memory. Only a hand-made rip has such a density.

Rips made with 1.0.0 keep their tags. Rip a game again to get the new lengths, voice counts and reverbs. The fixes for filtered voices and for hand-made rips work with existing rips.

## Other changes

- HSF now builds on two libraries in submodules: xsflib, for the players and rippers of the PSF family, and ntdlib, for the hardware and formats of Nintendo's consoles. To build from source, clone with `git clone --recursive`.
- The message for a damaged sound archive that lacks one of its tables now names the table. It used to be an internal error.

## Features

- **Ripping.** `hsfrip` rips a Switch game's files or a sound archive (`.bfsar`) into an `.hsflib` and a `.minihsf` for each sequence. The game's files are a folder or a Bezel Engine archive (`.bea`). The folder is the game's RomFS, once it's extracted from the game, or a folder that holds the RomFS. `hsfrip` reads the files inside a game's Bezel Engine archives too. It finds the group files that a game keeps outside its sound archive. The ripper plays each sound to work out its length and fade tags, and skips the sequences that make no sound. `--bgm` rips only the music. `hsfrip` also supports drag and drop.
- **The sound library.** The model follows the version of `nn::atk` in WarioWare: Get It Together! (SDK 10.4.1): its sequence player, envelopes, LFOs, filters, voices and mixes, with the Switch's 5 ms frames.
- **The console's mixing.** The Switch mixes its voices in an audio renderer that runs in the system rather than in the game. HSF does the renderer's work in code: the voices' decoding, sample-rate conversion, filters, volume and mix ramps and depop, and the mixes. The code does the same arithmetic as the renderer's build for the CPU in games' `sdk` modules.
- **Effects.** A game can put effects on the sound library's aux buses. HSF plays the I3DL2 reverb that a game runs on an aux bus. HSF's reverb does the same arithmetic as Nintendo's reverb, bit for bit, and the aux bus's 20 ms round trip is kept. For a game on Bezel Engine, `hsfrip` takes the reverb its scenes use, and the voice count its `boot.lua` gives the engine.
- **Rendering.** `hsfplay` renders rips to WAV or FLAC at 48,000 Hz.
- **foobar2000.** The component plays `.minihsf` files using their length and fade tags. Tag editing, ReplayGain and endless playback are supported. A separate thread renders ahead of playback and keeps up to ten minutes of audio. That makes seeking within a track quick.

## Known limitations

- The model follows WarioWare: Get It Together!'s version of the sound library. A game with another version may play differently from the console.
- Of the effects a game can use, only the I3DL2 reverb on an aux bus is played. The renderer's reverb and delay effects aren't. A game that isn't on Bezel Engine gets no reverb from `hsfrip`.
- A Bezel Engine game's scenes can name another reverb for a stage. `hsfrip` gives every rip the default one.
- The output is stereo. Surround isn't played.
- A sequence that depends on values the game sets plays as it does before the game sets any. A sequence that draws random numbers takes the same path every time.
- Sounds that play until the game stops them (such as ambiences) get two loops and a fade if the ripper can detect their loops. Otherwise, they play until their notes end. The limit is ten minutes.
- Only sequences are ripped. Use tools such as vgmstream for BFSTM and BWAV streams. Wave sounds aren't ripped. Sequences whose data is in a group file that can't be found are skipped.
- A seek back past the audio the component keeps renders from the start of the track. Such seeks happen only in tracks longer than ten minutes and in endless playback.
- `hsfrip` refuses the Wii U's sound archives. They have the Switch's extension (`.bfsar`) but the other byte order.
- On Windows 10 before version 1903, `hsfrip` and `hsfplay` can't open a path with characters outside the system's code page.
- Encrypted games (NSP, XCI and NCA files) aren't read.
