In HSF 1.1.4, a rip's library holds only the files of the sound archive that its sequences play. A later rip into the same folder keeps the libraries of earlier rips. What the rips play is unchanged from 1.1.3.

HSF rips Nintendo Switch sequenced music into a PSF-family format. It plays the music with a model of the SDK's sound library and of the console's audio renderer, with the reverb a game puts on the music. The release includes a ripper (`hsfrip`), a renderer (`hsfplay`), a foobar2000 component and an XMPlay plugin. `docs/hsf.md` describes the format.

## New in 1.1.4

- **Smaller libraries.** An `.hsflib` held the whole sound archive. The archive in the `.hsflib` now holds only the files that the ripped sequences play: each sequence's file, the files of its banks, and the wave archives that those banks name. A group's file, in the archive or beside it, stays only when the model reads a copy of one of those files from it. The model reads nothing else. A rip made with `--bgm` or `--only` therefore takes far less space. The rips play as before. `hsfrip` reads each kept file back from the new archive and checks that it's the same. When the cut fails, `hsfrip` prints a warning. The `.hsflib` then holds the whole archive. `docs/hsf.md` describes the cut archive's layout.
- **Two rips into one folder.** A library now depends on the sounds that its rip takes. An `.hsflib` that differs from one of the same name in the folder therefore gets the next free name, such as `<name>_2.hsflib`. The rips already in the folder then still play. A library with the same contents keeps its name. To replace earlier rips, rip into an empty folder.
- **The libraries.** HSF now builds on xsflib 1.6.0 and ntdlib 1.12.0.

## Features

- **Ripping.** `hsfrip` rips a Switch game's files or a sound archive (`.bfsar`) into an `.hsflib` and a `.minihsf` for each sequence. The game's files are a folder or a Bezel Engine archive (`.bea`). The folder is the game's RomFS, once it's extracted from the game, or a folder that holds the RomFS. `hsfrip` reads the files inside a game's Bezel Engine archives too. It finds the group files that a game keeps outside its sound archive. The ripper plays each sound to work out its length and fade tags, and skips the sequences that make no sound. `--bgm` rips only the music. `hsfrip` also supports drag and drop.
- **The sound library.** The model follows the version of `nn::atk` in WarioWare: Get It Together! (SDK 10.4.1): its sequence player, envelopes, LFOs, filters, voices and mixes, with the Switch's 5 ms frames.
- **The console's mixing.** The Switch mixes its voices in an audio renderer that runs in the system rather than in the game. HSF does the renderer's work in code: the voices' decoding, sample-rate conversion, filters, volume and mix ramps and depop, and the mixes. The code does the same arithmetic as the renderer's build for the CPU in games' `sdk` modules.
- **Effects.** A game can put effects on the sound library's aux buses. HSF plays the I3DL2 reverb that a game runs on an aux bus. HSF's reverb does the same arithmetic as Nintendo's reverb, bit for bit, and the aux bus's 20 ms round trip is kept. For a game on Bezel Engine, `hsfrip` takes the reverb its scenes use, and the voice count its `boot.lua` gives the engine.
- **Rendering.** `hsfplay` renders rips to WAV or FLAC at 48,000 Hz.
- **foobar2000.** The component plays `.minihsf` files using their length and fade tags. Tag editing, ReplayGain and endless playback are supported. A separate thread renders ahead of playback and keeps up to ten minutes of audio. That makes seeking within a track quick. A seek back past that audio starts from a saved state of the player.
- **XMPlay.** The plugin plays `.minihsf` files using their length and fade tags. Endless playback is supported. Like the component, the plugin renders ahead of playback, keeps up to ten minutes of audio and seeks back from saved states.

## Known limitations

- The model follows WarioWare: Get It Together!'s version of the sound library. A game with another version may play differently from the console.
- Of the effects a game can use, only the I3DL2 reverb on an aux bus is played. The renderer's reverb and delay effects aren't. A game that isn't on Bezel Engine gets no reverb from `hsfrip`.
- A Bezel Engine game's scenes can name another reverb for a stage. `hsfrip` gives every rip the default one.
- The output is stereo. Surround isn't played.
- A sequence that depends on values the game sets plays as it does before the game sets any. A sequence that draws random numbers takes the same path every time.
- Sounds that play until the game stops them (such as ambiences) get two loops and a fade if the ripper can detect their loops. Otherwise, they play until their notes end. The limit is ten minutes.
- Only sequences are ripped. Use tools such as vgmstream for BFSTM and BWAV streams. Wave sounds aren't ripped. Sequences whose data is in a group file that can't be found are skipped.
- `hsfrip` refuses the Wii U's sound archives. They have the Switch's extension (`.bfsar`) but the other byte order.
- On Windows 10 before version 1903, `hsfrip` and `hsfplay` can't open a path with characters outside the system's code page.
- Encrypted games (NSP, XCI and NCA files) aren't read.
